# Решение задачи 01

## Запуск

Требуется PHP 8.1 или новее. Из корня репозитория:

```bash
php tasks/01-orders-1c-sync/run.php
php tasks/01-orders-1c-sync/bugs/OrderTotal.php
```

Первый аргумент `run.php` — путь к JSON-ответу API, второй — путь к CSV-выгрузке 1С. Благодаря этому файловый источник заказов можно заменить HTTP-клиентом, не меняя сверку.

Скрипт создаёт:

- `var/reconciliation-report.csv` — отчёт для менеджера, UTF-8 с BOM, разделитель `;`;
- `var/sync.log` — ошибки и предупреждения обработки.

## Принятые решения

- В обработку и резерв остатков попадают только статусы `new` и `confirmed`; `cancelled` остаётся в отчёте, но не передаётся и не резервирует товар.
- Артикул нормализуется: обрезаются пробелы и приводится регистр. Поэтому ` ts-1002` сопоставляется с `TS-1002`.
- Резерв рассчитывается суммарно по всем уникальным активным заказам. Это выявляет дефицит, который не виден при проверке каждого заказа изолированно.
- Повтор ID заказа не резервируется и не передаётся до ручной проверки — это защищает от двойной отгрузки. В отчёте остаётся одна строка на позицию с количеством повторов.
- Две карточки 1С с одним артикулом считаются ошибкой справочника: строка заказа блокируется, а не сопоставляется с произвольной карточкой.
- Цена сравнивается с допуском 0,01 BYN. Некорректные строки не останавливают весь запуск: они отражаются в отчёте и логе.
