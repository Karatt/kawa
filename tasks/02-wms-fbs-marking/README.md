# Решение задачи 02

## Запуск

Нужен PHP 8.1+:

```bash
php tasks/02-wms-fbs-marking/run.php
```

Скрипт создаёт в `var/` три CSV в UTF-8 с BOM (разделитель `;`) и `processing.log`:

- `pick-list.csv` — отсортированный маршрут подбора по ячейкам;
- `assembly-control.csv` — решение по каждому заданию: отгружать или остановить;
- `inventory-differences.csv` — только значимые расхождения и непересчитанные ячейки.

## Итог для экзаменатора

Прогон на предоставленных данных сформировал 16 строк листа подбора, 7 проблемных заданий и 5 инвентаризационных расхождений. Только `T-5007` прошёл контроль сборки без замечаний; для `T-5008` не хватило воды, потому что приоритет по сроку отгрузки отдал остаток более срочному заданию.

- [Лист подбора](var/pick-list.csv) показывает маршрут по ячейкам и недоступную позицию `WH-2008`.
- [Контроль сборки](var/assembly-control.csv) фиксирует повтор КИЗ, КИЗ с чужим GTIN, отсутствие КИЗ, лишние и недостающие сканы.
- [Расхождения инвентаризации](var/inventory-differences.csv) отделяет вероятное неучтённое перемещение от возможного несинхронизированного списания, неполного пересчёта и неизвестного излишка.

## Принятые решения

- Дефицит распределяется по самому раннему `ship_by`; при одинаковом сроке — по `task_id`. Товар из нескольких ячеек берётся последовательно по адресу ячейки.
- Вода `WH-2008` полностью выделяется более срочному `T-5007`; `T-5008` отмечается как невыполнимое по этой позиции, но доступный скотч остаётся в листе подбора.
- Для маркированного товара проверяются наличие КИЗ, соответствие GTIN штрихкоду и уникальность КИЗ во всём журнале. Любая проблема останавливает отгрузку задания.
- Отсутствующая строка пересчёта означает не нулевой остаток, а незавершённую инвентаризацию. Равные по товару, но разнонаправленные расхождения ячеек считаются неучтённым перемещением до подтверждения.

## Что изменить в процессе

Сканирование нужно привязать к открытому заданию: система не должна принимать товар, которого в нём нет, и должна блокировать закрытие при недостающем КИЗ. КИЗ следует резервировать сразу при первом успешном скане, чтобы повторное использование отклонялось мгновенно. Списание из ячейки и регистрация перемещения должны происходить в той же транзакции, что и подтверждение подбора. Перед проведением инвентаризации нужно блокировать движения по ячейке либо фиксировать их во времени, а незакрытые ячейки нельзя трактовать как нулевой остаток.
