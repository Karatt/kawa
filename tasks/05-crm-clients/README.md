# Решение задачи 05

## Запуск

Нужен PHP 8.1+:

```bash
php tasks/05-crm-clients/run.php
```

Скрипт читает исходные CSV и создаёт в `var/`:

- `duplicates-report.md` — рекомендации по группам дублей и похожим, но разным карточкам;
- `processing.log` — журнал обработки.

Исходные карточки и обращения не меняются: отчёт предлагает главную карточку, но не выполняет слияние.

## Итог для экзаменатора

На предоставленных данных выявлено три группы точных дублей и две пары, которые не следует объединять автоматически.

- [Отчёт по дублям](var/duplicates-report.md): «Альфа» (`C-1001`/`C-1014`), «Бета» (`C-1003`/`C-1017`/`C-1022`) и «Йота» (`C-1009`/`C-1024`). После ручного подтверждения в главные карточки перейдут соответственно 2, 2 и 2 обращения.
- [Проектирование модели обращений](05-design.md): поля и связи, статусы, SLA/эскалация, а также защита от дублей на сайте, в обмене с 1С и при ручном вводе.

Совпадение только имени («Гамма») или только телефона («Зета»/«Ро») не признано дублем: остальные реквизиты конфликтуют. Это снижает риск ошибочно объединить разных контрагентов.

## Принятые правила

- УНП из 9 цифр — сильный идентификатор. Телефон приводится к формату `375...`, e-mail — к нижнему регистру без пробелов, название очищается от организационно-правовой формы и пунктуации.
- В группу попадают карточки с одинаковым УНП либо как минимум с двумя совпавшими нормализованными признаками из телефона, e-mail и названия. Главная выбирается по числу обращений, заполненности реквизитов, затем по более раннему созданию.
- Совпадение лишь одного слабого признака не запускает слияние: оно попадает в раздел ручной проверки отчёта.
